# QWEN.md — Voice-IME-Helper

## Project Overview

A [Hammerspoon](https://www.hammerspoon.org/) **Spoon** plugin that automatically switches back to the previous input method after a voice IME (e.g., Doubao/豆包语音输入) finishes. It detects voice input by monitoring microphone usage via `hs.audiodevice` and input source changes via `hs.keycodes`, then restores the prior input method when the microphone is released.

- **Language:** Lua
- **Runtime:** [Hammerspoon](https://www.hammerspoon.org/) (macOS only)
- **Type:** Hammerspoon Spoon plugin (single-file, no build system)
- **License:** MIT

## Architecture

The plugin implements a **three-state machine**:

```
IDLE ──(input source changed)──► CHECKING ──(mic becomes "in use")──► MONITORING
  ▲                                  │                                    │
  │                              (timeout)                          (mic released)
  │                                  │                                    │
  └──────────────────────────────────┘                                    │
  ▲                                                                       │
  └───────────────────────────────────────────────────────────────────────┘
```

| State | Purpose |
|-------|---------|
| `IDLE` | Waiting for input source change |
| `CHECKING` | Polling + watching mic for voice IME activation (with timeout) |
| `MONITORING` | Voice IME confirmed; waiting for mic to be released |

Detection uses **dual mechanisms** (watcher events + polling) for reliability. The `restoreDelay` prevents premature switching during speech pauses.

## Key Hammerspoon APIs Used

- `hs.keycodes.inputSourceChanged()` — monitor input method switches (single-callback; may conflict with other Spoons)
- `hs.keycodes.currentSourceID()` — read/set current input method
- `hs.audiodevice.defaultInputDevice()` — get the mic device
- `hs.audiodevice:inUse()` — check if mic is active
- `hs.audiodevice:watcherStart()` / `:watcherStop()` / `:watcherCallback()` — event-driven mic state changes
- `hs.timer.doAfter()` / `hs.timer.doEvery()` — delayed and periodic execution
- `hs.logger` — logging

## Installation & Usage

### Install (dev symlink)

```bash
ln -s /Users/elias/my/WorkNow/MyProjects/Voice-IME-Helper/VoiceIMEHelper.spoon \
      ~/.hammerspoon/Spoons/VoiceIMEHelper.spoon
```

### Enable in `~/.hammerspoon/init.lua`

```lua
hs.loadSpoon("VoiceIMEHelper")
spoon.VoiceIMEHelper:start()
```

### Configuration (set before `:start()`)

| Property | Default | Description |
|----------|---------|-------------|
| `checkDelay` | `0.5` | Seconds to wait after IME switch before checking mic |
| `checkInterval` | `0.3` | Mic polling interval (seconds) |
| `checkTimeout` | `3.0` | Max seconds to wait for mic activation before giving up |
| `restoreDelay` | `1.0` | Seconds to wait after mic release before switching back |
| `voiceIMEPatterns` | `nil` | Lua patterns to filter which IMEs trigger monitoring (e.g., `{"语音", "Voice", "Dictation", "Doubao"}`) |
| `logLevel` | `"info"` | `"debug"` / `"info"` / `"warning"` / `"error"` |

## Public API

| Method | Description |
|--------|-------------|
| `:start()` | Begin monitoring |
| `:stop()` | Stop monitoring, clean up |
| `:getState()` | Returns `"IDLE"`, `"CHECKING"`, or `"MONITORING"` |
| `:getPreviousSourceID()` | Returns the saved input source ID to restore to |
| `:triggerManualRestore()` | Manually switch back to saved IME |
| `:setLogLevel(level)` | Change log level at runtime |
| `:bindHotkeys(mapping)` | Bind hotkeys (supports `restore` action) |

## Development Conventions

- **Single-file architecture** — all logic lives in `VoiceIMEHelper.spoon/init.lua`. Do not split into multiple files without strong reason.
- **Spoon metadata** — `docs.json` follows the [Hammerspoon Spoon documentation format](https://github.com/Hammerspoon/hammerspoon/blob/master/SPOON.md). Keep it in sync when adding/changing public API.
- **Dual detection** — both `hs.audiodevice` watcher events and timer-based polling are used together. When modifying mic detection logic, keep both paths consistent (same `micDevice` reference, coordinated `restoreTimer`).
- **State machine discipline** — all state transitions go through `stopMicMonitoring()` (to IDLE) or `transitionToMonitoring()`. Timer and watcher cleanup must happen on every transition.
- **Logging** — use the module-level `logger` (`hs.logger`). Respect `obj.logLevel`. Use `logger.d` for state transitions, `logger.i` for user-visible events, `logger.w`/`logger.e` for failures.
- **No external dependencies** — only Hammerspoon built-in modules.

## Known Limitations

- `hs.keycodes.inputSourceChanged` supports only one callback system-wide — conflicts with other Spoons using the same callback.
- Voice IMEs that don't trigger an input source switch (e.g., global hotkey within current IME) cannot be auto-detected.
- `hs.audiodevice:inUse()` reflects system-level audio device state, not app-specific mic usage.
